## 1. 현재 동작

`housing_agent`: RAG k=3 검색 → 검색 조문 근거로 Bedrock 답변 생성 → **citations = 검색 chunks 전부**, **confidence 0.8 고정**.

```python
chunks = _rag.search(query, k=3)
answer, conf = _generate_answer(query, chunks)   # conf 항상 0.8
"citations": [ {...} for c in chunks ]           # 검색된 3개 전부 그대로
```

## 2. eval 16문항 실답변 리뷰 — 발견

### 발견 A — 근거(citation)와 답변 불일치 ★이번 타깃(C)★
화면 `citations`는 **검색 top-3 그대로**라, 답변이 실제 사용한 조문과 자주 어긋남.

| Q | 답변이 실제 다룬 조문 | 화면 근거(검색 top-3) | 문제 |
|---|---|---|---|
| 1 보증금 안돌려줘 | 제4조2항+일반론 | **제6조·제6조의3**·제4조 | 보증금 답에 갱신 조문이 근거로 |
| 4 확정일자 | **제3조의2** | 제3조의6·제8조·제7조 | 답변 핵심 조문이 근거에 **아예 없음** |
| 8 계약연장 | 제6조의3 | **제4조·제6조**·제6조의3 | 무관 조문 2개 노출 |

→ 16개 중 **대부분이 3개 근거 중 1~2개가 답변과 무관**. 차별점("현행 법령 **근거**") 신뢰성 직격.

### 발견 B — confidence 0.8 고정 (후속 ⑤)
검색 미스(Q4)든 적중(Q5)이든 confidence 0.8 동일 → 무의미. verifier 임계(0.5) 판단에 정보 안 줌.

## 3. 개선 방안

### C. citation 가지치기 (이번 작업 — 발견 A)
- LLM이 답변과 함께 **"실제 근거로 쓴 조문 번호(`used`)"** 를 반환 → **그 조문만 citation**으로.
- `used` 형식: 검색 조문에 매긴 **인덱스 배열**(예 `[1,3]`) — 문자열("제3조의2") 매칭보다 견고.
- `used`가 비면(답이 검색 조문을 하나도 안 씀, 예: Q4 완전 검색미스) → **안전하게 전체 유지**(현행). C의 목적은 "일부만 쓴 흔한 케이스의 무관 조문 제거"이고, 완전 검색미스는 검색 E 영역.
- 범위: **`agents/housing.py`만**. RAG·verifier·planner 불변.

### ⑤ 동적 confidence (후속, 발견 B)
RAG score 기반으로 confidence 산출 — 검색 빈약하면 낮게 → 약한 답을 verifier가 자연 탈락. (C 다음 별도)
